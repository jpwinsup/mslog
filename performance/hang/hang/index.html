システム ハングが発生した場合の調査

本記事はマイクロソフト社員によって公開されております。

こんにちは。 Windows Performance チームの栗木です。本ブログでは、システム ハングが発生し、端末の操作ができなくなった場合に採取いただきたい資料についてご紹介いたします。

システム ハングが発生した場合は、BSOD (※) の強制実行が可能であるかや、実行した後にメモリ ダンプ ファイルが出力されるかどうかによって対応が変わりますので、まず、BSOD の可否と、実施後のメモリ ダンプ ファイルの出力有無をご確認ください。

※ BSOD: Stop code error, Bug check, Kernel error, Blue Screen error, Black Screen error

システム ハングが発生してから資料採取までの流れは、以下になり、 [A] メモリ ダンプ ファイルが出力されている場合と[B] メモリ ダンプ ファイルが出力されなかった場合で採取する資料が異なります。

BSOD を発生させる方法

NMI または、キーボードから BSOD を発生させる方法は、以下の Web サイトに記載がございますので、こちらをご確認ください。

ブルースクリーンの強制実行
https://jpwinsup.github.io/blog/2021/02/15/Performance/Hang_BSOD/ForcingSystemCrash/

※ キーボードから BSOD を強制実行するためには、事前にレジストリ設定が必要になります。

BSOD を実行できた場合は、OS 起動後にメモリ ダンプ ファイルの出力先 を確認してください。
BSOD を実行できなかった場合は、メモリ ダンプ ファイルを出力できないので、[B] メモリ ダンプ ファイルが出力されなかった場合へ進んでください。

メモリ ダンプ ファイルの出力先

メモリ ダンプ ファイルの出力先は、レジストリ HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\CrashControl に 保存されていますので、管理者権限で起動したコマンド プロンプトまたは、PowerShell で以下のコマンドを実行することで確認できます。

reg query "HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\CrashControl"

実行結果例：
HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\CrashControl
    AutoReboot    REG_DWORD    0x1
    CrashDumpEnabled    REG_DWORD    0x7
    DumpFile    REG_EXPAND_SZ    %SystemRoot%\MEMORY.DMP <- メモリ ダンプ ファイルの出力先
    DumpLogLevel    REG_DWORD    0x0
    EnableLogFile    REG_DWORD    0x1
    LogEvent    REG_DWORD    0x1
    MinidumpDir    REG_EXPAND_SZ    %SystemRoot%\Minidump <- ミニ ダンプ ファイルの出力先
    MinidumpsCount    REG_DWORD    0x5
    Overwrite    REG_DWORD    0x1
    DumpFilters    REG_MULTI_SZ    dumpfve.sys
    AlwaysKeepMemoryDump    REG_DWORD    0x0

デフォルトの出力先は、 %SystemRoot%\MEMORY.DMP になりますので、設定を変更していなければ、C:\Windows\MEMORY.DMP へ出力されます。出力先の設定を変更している場合には、DumpFile に設定されている出力先にメモリ ダンプが出力されているか確認してください。

BSOD が発生した環境によっては、MEMORY.DMP ファイルを出力できず、%SystemRoot%\Minidump へミニダンプ(※) が出力される場合がございます。MEMORY.DMP ファイルが出力されていない場合には、Minidump のフォルダへアクセスしてミニダンプが出力されているか確認してください。

※ ミニダンプは、メモリ ダンプの一種ですが、詳細な解析の実施をするには情報量が少ないダンプファイルになります。ミニダンプの詳細については、以下の Web サイトをご覧ください。

参考 URL： Small Memory Dump
https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/small-memory-dump

[A] メモリ ダンプ ファイルが出力されている場合

ハング発生中のスクリーンショットとメモリ ダンプに加えて、システム情報、OS バージョン情報、レジストリ、イベント ログを確認いたしますので、メモリ ダンプ ファイルと以下のデータをご提供ください。メモリ ダンプの解析結果より、追加で資料が必要になる場合がございます。

1. システム情報

管理者権限で起動したコマンド プロンプトまたは、PowerShell で以下のコマンドを実行し、出力されたファイルをご提供ください。

msinfo32.exe /nfo C:\path\to\msinfo32.nfo
systeminfo.exe > C:\path\to\systeminfo.txt

※ C:\path\to\ は任意のパスに変更してください。

msinfo32
https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/msinfo32
systeminfo
https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/systeminfo

2. OS バージョン情報

ファイル名を指定して実行（Windows ロゴ キー + R）から winver を実行し、Windows のバージョン情報 を表示させ、スクリーンショットをご提供ください。

3. レジストリ

管理者権限で起動したコマンド プロンプトまたは、PowerShell で以下のコマンドを実行し、出力されたレジストリ ファイルをご提供ください。

reg export HKLM C:\path\to\hklm.reg
reg export HKCU C:\path\to\hkcu.reg
reg export HKU C:\path\to\hku.reg

※ C:\path\to\ は任意のパスに変更してください。

4. イベント ログ

以下のファイルをコピーしてご提供ください。

  • C:\Windows\System32\winevt\Logs\Application.evtx
  • C:\Windows\System32\winevt\Logs\Setup.evtx
  • C:\Windows\System32\winevt\Logs\System.evtx

※ イベントログの出力先を変更している場合は、変更したパスにあるイベントログファイルをご提供ください。

[B] メモリ ダンプ ファイルが出力されなかった場合

メモリ ダンプが出力されていない場合、システム ハングの調査はできないため、原因の特定が困難ですが、システム構成やログから過去の類似事例を調査いたしますので、ハング発生中のスクリーンショットと以下の Web サイト記載の資料採取をお願いします。

初期調査にご取得いただくログ情報

また、次回発生時に備えて、以下の Web サイトを参考に BSOD の実行方法の確認と BSOD 発生時にメモリ ダンプが出力されるように設定変更をするご検討をお願いいたします。
